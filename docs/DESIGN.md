# Design notes

**Target:** Minecraft 1.21.1 · NeoForge 21.1.265 · ModDevGradle 2.0.148 · Java 21 · Parchment 2024.11.17
**Mod id:** `reikos_signal_tower` · **Package:** `com.reiko.signaltower`

## Rules

- **Publishing (CurseForge only):** the `Build` workflow's `curseforge` job runs after `build` (tests) on `main`. It reads `mod_version` and `curseforge_project_id` from `gradle.properties`; it stops with a notice if the `CURSEFORGE_TOKEN` secret or the id is missing, and stops if the tag `v<mod_version>` exists. Otherwise it downloads the tested jar artifact, runs `.github/scripts/curseforge_upload.py` (standard library only: `GET /api/game/version-types` and `/api/game/versions` on minecraft.curseforge.com to find the ids of Minecraft 1.21.1 (type slug `minecraft-1-21…`, not Bukkit's), NeoForge (`modloader`), Java 21 (`java`), Client and Server (`environment`); then `POST /api/projects/<id>/upload-file` multipart with `metadata` (the `## <version>` section of `CHANGELOG.md` as Markdown, display name "Reiko's Wireless Redstone <version>", `release`, optional dependencies jade, wthit-forge, jei, emi, journeymap, xaeros-minimap; on HTTP 400 once more without them) and `file`; header `X-Api-Token`), then pushes the tag. CC: Tweaked and Reiko's Weather aren't listed: neither has a 1.21.1 NeoForge file on CurseForge. Tested against a fake server (good upload, bad token, no token, unreachable, a refused slug, no changelog section, a bad id) and with `actionlint`. Setup and release steps: `docs/PUBLISHING.md`.
- **The name (v0.68.1):** the mod is called **Reiko's Wireless Redstone** (before v0.68.1: Reiko's Redstone Signal Tower). Only what players read changed: `mod_name` (the Mods screen, Jade's and WTHIT's mod line, JEI and EMI), the advancement tab's root, the key binds' category, the config screen's title, the jar (`reikos_wireless_redstone-<version>.jar`) and the CI artifact. The mod id stays `reikos_signal_tower` (every block, item, entity, component, sound, recipe, advancement and saved file is keyed by it, so changing it would empty old worlds), as do the package `com.reiko.signaltower`, the class names, the server config file (`reikos_signal_tower-server.toml`) and the Gradle project name. The GitHub repository was renamed to match: https://github.com/Reiko45/Reiko-s-Wireless-Redstone (GitHub forwards the old Reiko-s-Redstone-Signal-Tower address).
- **Frequencies** are whole numbers from 1 to 999,999,999, stored in each transmitter, receiver and repeater's block entity (NBT key `frequency`). New blocks start on 1.
- **Reach** belongs to transmitters and repeaters: `baseReach + reachPerBlockOfHeight × max(0, y − seaLevel)`, capped by `maxReach` if that's above 0. Defaults are 32 and 8, with no cap.
- **Links:** a receiver hears a transmitter or repeater on its frequency if their *horizontal* distance is at most its reach. Height difference doesn't matter.
- **Radio Repeater:**
  - Listens for its frequency at its own position (like a receiver there) and sends the strongest signal it hears out again with its own reach, at the same strength. No redstone input.
  - It hears transmitters, remote pulses and latches, and other repeaters, but only signals that trace back to a real transmitter or remote press: two repeaters can't keep each other on.
  - Like a transmitter, it relays remote presses on any frequency when it's within the player's reach (`towersRelayRemotes`).
  - `LIT` block state (light level 7, amber sparks) while repeating. Recipe: Radio Receiver + Radio Transmitter (shapeless).
- **Wall Redstone on ceilings and round corners (v0.52.0):** `facing` takes every value but up; down hangs it under a block (needs a sturdy bottom face), its arms fixed to the compass (up = south, down = north, left = west, right = east, as its model is turned x 270). An arm also connects round an outside corner: when the space beside it in that direction isn't a redstone conductor, to Wall Redstone in the space past that edge stuck to the same block (the next wall, or the ceiling under it), or over a wall's top edge to vanilla dust on the block. Corner neighbours count as wires (their power − 1). Vanilla dust doesn't see us diagonally; dust on a conductor block reaches the wall through the block anyway.
- **Old radio towers (v0.55.0):** a structure (`reikos_signal_tower:radio_tower`, type of the same name, step `surface_structures`, `terrain_adaptation: beard_thin`) in the biome tag `has_structure/radio_tower` (plains, sunflower plains, meadow, cherry grove, savannas, windswept hills, taigas incl. snowy and old-growth, snowy plains, desert, badlands, sparse jungle, grove), structure set `radio_towers` (random spread, spacing 24, separation 8, salt 1408155011). One piece 12 × 9 × (masts + 3), turned at random. Plan (decided at the start, saved in the piece): masts 6–10; on the air 60%; frequency 100,000–999,999; Iron Antenna 30%. On the air: redstone torch at the mast's foot, battery 30,000–80,000 with a solar panel, aviation beacon on top, 3 guy anchors, platform ring round the mast one below the top. - **Raid alerts (v0.58.0):** every 40 ticks a village station looks for a raid within 96 blocks (`ServerLevel.getRaidAt`, the game's own "raided" distance; stopped raids don't count). A new one that's still going: it follows that raid (its id), sends 15 whatever its redstone (`inputOf` takes the higher), and telegraphs "RAID! Pillagers are coming to the village" as "Village Radio" over its own coverage (`stationCoverage`, like the weather station; not while silenced or out of power), with a bell note (and, since v0.59.0, the `station.siren` sound at volume 3, heard 48 blocks round, unless it's down). Each new wave (`getGroupsSpawned` above the last announced): "Raid: wave N of M", M = `getNumGroups(difficulty)` + 1 if the raid omen level is above 1. Victory / loss: "The raid is over: the village held" / "fell", and the alert ends. The followed raid gone (stopped, or another id): "The raid has ended". A raid already over when first seen is ignored. Saved `raid_id`, `raid_wave`, `raid_waves`. `raidAlerts` (on) off: no alerts, and one in progress just ends.
- **Computers (v0.58.0, CC: Tweaked):** peripherals on every side: `radio_transmitter` (Radio Transmitter and Compact; the block entity type they share), `radio_receiver` (every receiver kind), `radio_telegraph`. A computer's strength (0–15, not saved) is sent if higher than the redstone; when the last attached computer detaches it goes back to 0 (on the server thread). `setFrequency` follows the tuner's rule for senders (refused onto a private frequency the block's tuner isn't allowed on); receivers and telegraphs may be set anywhere. `listen(f)` and `scan()` hear as the block's tuner (deaf to someone else's encrypted frequency). A telegraph sends as "Computer N" under its tuner's permission (no intruder alert: no player), with the telegraph's cooldown. Events: `radio_signal` (attachment name, frequency, strength) when what a receiver hears changes, `radio_message` (attachment name, frequency, text, from) when a readable message reaches a telegraph. Needs CC: Tweaked 1.114.0+ (`AttachedComputerSet`).
- **Sounds (v0.59.0):** nine variable-range `SoundEvent`s, each with one mono 44.1 kHz Ogg Vorbis file (the event's name with `_`, e.g. `tuner_tune.ogg`) and a subtitle `subtitles.reikos_signal_tower.<event>`. `tuner.tune` (static and a whistle, 0.5 s): a tuner tuning a block (BLOCKS 0.7, pitch 1.15), and any handheld copying a block's frequency (PLAYERS 0.6), in place of the amethyst chime. `tuner.step`: sneak + scroll (0.5, pitch 1.1 up, 0.95 down). `meter.tick`: the Signal Meter's tick (UI, 0.4, its pitch as before). `telegraph.key`: a message sent (0.7), and the Radio Operator's work sound. `telegraph.sounder`: the clicks of a telegraph that gets one (0.6, pitch 0.9 / 1.05). `pager.beep`: each of a pager's beeps (0.7). `tower.on` / `tower.off` (BLOCKS 0.7): only a full-size `radio_transmitter` block, when `POWERED` flips in `refresh`; not on its first refresh after loading (nor a found tower's first), and at most one per 40 ticks. `station.siren` (two tones, 1.6 s): a village station when a raid starts. The files come from `tools/make_sounds.py` (numpy synthesis with a fixed seed, ffmpeg libvorbis q5, bitexact), which also writes `sounds.json`.
- **Radio Jukebox (v0.60.0):** a full-size transmitter (reach by height, masts, antennas, power cost, relaying remote presses) with one disc slot (anything with `minecraft:jukebox_playable`). It sends 15 while its song plays, else 0 (`inputOf`). A disc put in (by hand: one item, not used up in creative; or a hopper) plays from then; one play is the song's `lengthInTicks` + 20 (as a vanilla jukebox). Redstone into it or its mast column: a rising edge plays it from the start and sets `loop`; while looping it repeats (a play's start is `start + n × length`); a falling edge moves `start` to the current play's and clears `loop`, so that play is the last. With a disc, stopped and powered, it starts. Empty hand (not sneaking) takes the disc out into the inventory; sneak + empty hand takes an antenna off. Broken: the disc drops (`onRemove`); moved by the mast builder or replaced by a command: it's cleared first (`Clearable`), so it isn't dropped as well as moved. Item handler (hoppers, pipes; one slot): insert a disc only when empty, extract only once it has stopped. Comparator: the song's `comparator_output` while it plays. Note particles every second while it plays. Turn-ons logged as `JUKEBOX` with the song as the detail. Recipe: Radio Transmitter + Jukebox (shapeless), and back.
- **Music broadcasts (v0.60.0):** a playing jukebox that's on the air (sending, not down, not kept quiet on someone else's private frequency) puts `Music(frequency, song key, start, length, loop)` in the network under its position (saved, so it plays on while its chunk is unloaded). The network's tick takes off a song that's over (not looping), and sets that jukebox's transmitter to 0 if it's still sending (its chunk may not be loaded); at each repeat of a looping one it bumps the frequency's revision. A Radio Speaker that hears its frequency (`listen` > 0, not deaf) plays the nearest jukebox's song on it that's playing, whose station coverage (its tower in the weather, dish included, plus repeaters on the frequency; worked out at most every 20 ticks) covers it; while it does, it doesn't ring (a turn-on or a repeat ring is skipped). The speaker sends clients (block entity update tag, speakers only) the song and when the current play began; a client plays it from there (the stream skips that far), at volume quiet 0.5 / normal 2 / loud 4 (heard 16 / 32 / 64 blocks), only the 4 nearest within earshot (kept until 16 blocks past it), and shows "Now Playing" once a play. Music doesn't go through an Ender Antenna or a converter.
- **Satellites (v0.61.0):** a Launch Pad holds a Satellite (slot 0, 1) and up to 8 Firework Rockets (slot 1, all with the same components); hoppers fill both, and take them out except while it climbs. Redstone off → on (`neighborChanged` → `redstone`) launches it if `launchProblem` is null: in order `launching`, `no_satellite`, `fireworks` (fewer than 8), `no_space` (the dimension has no skylight or has a ceiling: the Nether, the End), `no_sky` (`canSeeSky(pos.above())`, the skylight there, so glass is fine and a new roof counts once the light updates). A refusal is kept for Jade (not saved), plays `DISPENSER_FAIL` and goes to the action bar of players within 24 blocks. A launch uses both slots, picks a random seed, plays `satellite.launch` (BLOCKS 4, heard 64 blocks) and climbs for `FLIGHT_TICKS` 120: height 240 × (t/120)² above the deck. Then (in the server tick, or at once if the pad is broken while it climbs) `SignalNetwork.addSatellite(gameTime, seed)`: chat "Satellite in orbit over <dimension> (<n> up)" to players within 256 blocks, and the tower event `satellite_in_orbit` (value = n) for players within 64. A dimension keeps 64 (the oldest drop out). Comparator: 0 while climbing, else rockets (≤ 8) + 7 with a satellite.
- **Satellite paths (v0.61.0):** from the seed (`java.util.Random`): azimuth 0–360°, tilt 10–70° from overhead, period 3600–8399 ticks, phase 0–360°; the direction at game time t is `along·cos(a) + across·sin(a)`, a = phase + 2π (t − launched) / period, with `along` horizontal at the azimuth and `across` = up·cos(tilt) + side·sin(tilt). Clients get the list for their dimension at login, dimension change, respawn and each new satellite, and draw each one above the horizon after the sky (`AFTER_SKY`) at 100 blocks, half-size 1, the beacon glow texture, warm white, alpha = star brightness × (1 − rain) × 2 × min(1, y / 0.12); not under water, lava or powder snow, nor while blind; normal-sky dimensions only.
- **Satellite Dish (v0.61.0):** `AntennaTier.SATELLITE` (item `satellite_dish`), on full-size transmitters only (`sendsAcross`, as the Ender Antenna; the jukebox and bundled transmitter too). Each refresh tells the network whether it has one with `canSeeSky(pos.above())` (`uplinks`, saved). Uplinked = in `uplinks` and the dimension has a satellite. An uplinked tower's `linkReach` is `UPLINK_REACH` 60,000,000 (so the meter's margin is huge: the HUD shows "no edge: through a satellite" from half that), `hillLoss` from it is 0, `listenDirect` offers it unfaded (`offerFar`), and its music covers everywhere. Its own dimension only (phantoms are unchanged). Power: `rateFor` × 4 while uplinked. Not uplinked, it's reach as with no antenna. The first satellite over a dimension (and clearing them) re-checks every uplinked tower.
- **Map waypoints (v0.61.0):** every 100 ticks each player's list is worked out and sent if it changed (and again after logging in): their own towers in every dimension (non-compact transmitters, repeaters and converters, jammers whose `tunedBy` is them; reach = the stored reach, −1 if uplinked), then the places they've found (an attachment `discovered_towers`, list of dimension, pos, kind 3 old tower / 4 village station, frequency; copied on death; up to 256, oldest dropped), with the frequency the network has there now if any. An old tower or village station's block entity looks every 40 ticks for non-spectators within 96 blocks. Up to 512 entries. The client adds the target of the first Signal Scanner with one (hands, then inventory), checked each second. JourneyMap: a non-persistent group "Radio towers", a client waypoint each (color by kind), and for own towers with reach > 0 a 64-point polygon (stroke 0.8, fill 0.08) on the full map, minimap and webmap; redone when the list changes, cleared when mapping stops. Xaero's Minimap: third-party waypoints under `reikos_signal_tower:radio_towers` in the current world's container, the current dimension's only, initials TX/RP/JM/OT/VS/SC, redone when the list, the dimension or the container changes; any error turns it off for the session.
- **Morse Key (v0.62.0):** down while `now < heldUntil` (a player's use sets it to now + `RELEASE_TICKS` 7; the client repeats a held use every 4 ticks; the press is seen in the tick after, so a click is down 6 ticks) or while it has redstone (`maySend` as `tunedBy`, else nothing goes out). A player who may not send on the frequency is refused ("private_refused_morse") and the owner gets an intruder alert. A hand press that starts no more than `MERGE_TICKS` 1 after the key went up carries on the press before it (a held click whose repeat came late). Key down: the first press of a message fixes the coverage (`Telegraph.coverage`, as a telegraph there), later ones add a gap; the block state `down`, `telegraph.key` at 0.35 / 1.3. While down, `SignalNetwork.keyMorse` each tick (a remote pulse on the frequency until now + 3, `bump` only when new; `morseUntil` = now + `MORSE_QUIET_TICKS` 100, and one `MORSE` log entry when the frequency wasn't already carrying Morse). Key up: the press's length, `releaseMorse` (pulse removed, `bump`). The message ends `END_TICKS` 60 after the last key up, or at 512 presses, or once it decodes to 64 characters: `Morse.decode(…, finished, byHand)`, `Telegraph.clean`, and if not empty `Telegraph.morseMessage` (recorded and delivered as a telegraph message, from the keyer's name or "Morse Key"), "Sent in Morse: <text> (<read by>)" on the keyer's action bar if within 64 blocks. Nothing about a message being keyed is saved; re-tuning drops it.
- **Morse decoding (v0.62.0):** presses and gaps in ticks. If the longest press is at least twice the shortest, a press is a dash from 2 × the shortest, and a dot is the mean of the presses under that. Otherwise all are one kind: by hand (any press in the message a player's), dots if the mean is under `HAND_DASH_TICKS` 13, else dashes; by redstone, dashes if the mean is at least 2 × the shortest gap, dots if at most half of it, else as by hand. All dashes: a dot is the mean / 3. A gap of 2 dots or more ends a letter, 5 or more a word. Codes: A–Z, 0–9 and . , ? ' ! / ( ) & : ; = + - _ " $ @ (`Morse.sendable` upper-cases, drops the rest, collapses spaces); an unknown code is `*`. Jade: `morse_keyed` (decoded letters, the last one only once its gap is 2 dots), `morse_letter` (`pendingCode`), `morse_last`, `morse_down`.
- **Telegraph in Morse (v0.62.0):** `telegraph_morse` (saved). With it on, `Telegraph.send` keys `Morse.sendable(text)` ("telegraph_morse_nothing" if empty) at `TELEGRAPH_UNIT` 2 ticks a dot (dash 3, gap in a letter 1, between letters 3, between words 7 units), sound at each element's start, `keyMorse`/`releaseMorse` as the key; at the end `markSent` and `Telegraph.morseMessage`. While keying, sending is refused ("telegraph_keying"), the screen's Send reads "Keying..." and Jade says "Keying". Nothing is saved about the keying (unloaded, it stops and the frequency is released).
- **Speaker Tone (v0.62.0):** `SpeakerSound.TONE` (id 10), `whileOn`: it never plays on a turn-on or a repeat (particles still do). Clients play a looping `speaker.tone` (740 Hz with a little 1480 Hz, linear falloff over the volume's range) at the speaker's note pitch while its `POWER` > 0 and no music, kept alive each client tick and stopped the tick after it's off.
- **Pagers and Morse (v0.62.0):** a frequency carrying Morse (`isMorse`, up to 100 ticks after the last element) doesn't set off pagers on a turn-on; the message at the end does.
- **Mod icon (v0.62.0):** `logoFile = "reikos_signal_tower_logo.png"`, `logoBlur = false` in the mods.toml, a 512 × 512 PNG at the jar's root, drawn by `tools/make_logo.py` (also `docs/images/icon.png`).
- **Ticker Tape Printer (v0.63.0):** a `RadioBlock` with `FACING`, `BOOK`, `PRINTING`; one slot holding a Book and Quill (being printed in) or a written book (a finished logbook). Every `CHECK_TICKS` 10 (staggered by position) it takes `SignalNetwork.messagesAt(frequency, pos)` and prints those after its mark (`seenTime`, the game time of the last printed, and `seenCount`, how many of that tick's it printed; set to the current tick, counting that tick's messages as seen, on its first tick and after a re-tune), oldest first, while it holds a Book and Quill. An entry is "Day %s, %s, %s:" (`PagerItem.dayAndTime`, the sender's name) and the text on the next line, or "(encrypted)" if its tuner may not hear the frequency; entries go on the last page if `lines(page) + 1 + lines(entry) <= LINES_PER_PAGE` 13 (a line per 18 characters, at least one per text line), with a blank line between, else on a new page. With 50 pages and no room, the book is signed: `transmuteCopy(WRITTEN_BOOK)`, title "%s log" with the frequency's label (cut to 32), author the block's name, generation 0, the pages as literal components; the message waits. Printing sets `PRINTING` for 24 ticks and plays `printer.print` (BLOCKS 0.7); signing plays `BOOK_PAGE_TURN`. Hoppers: insert only a Book and Quill into an empty slot (one), extract only a written book. By hand: a Book and Quill loads (one used, not in creative); an empty hand takes the book out; sneak for the status. Comparator: 0, 1 + pages × 13 / 50, or 15 for a logbook. Breaking drops the book. Saved: `printer_book`, `printer_seen_time`, `printer_seen_count`, `printer_printed`, `printer_last_text`, `printer_last_from`. Jade: `printer_book` (none / writing / full), `printer_pages`, `printer_max`, `printer_count`, `printer_waiting`, `printer_last_text`/`_from`.
- **WTHIT (v0.63.0):** `waila_plugins.json` names `compat/wthit/SignalTowerWthitCommon` (`IWailaCommonPlugin`: `blockData` for each of `WthitBlocks.COVERED`, writing `RadioInfo.read(level, pos, player)` under `reikos_signal_tower` in `data.raw()`) and `SignalTowerWthitClient` (`IWailaClientPlugin`: `body` at priority 1100, `RadioInfo.lines(state, data)`). - **Wall Redstone:**
  - `facing` points away from the wall. Its `up`/`down`/`left`/`right` arms are drawn only toward in-plane neighbors, using vanilla's dust textures, tinted with `RedStoneWireBlock.getColorForPower`.
  - Power works like vanilla dust:

    - it takes the best non-wire signal from all 6 neighbors, or the strongest neighboring wire (its own or vanilla dust) minus 1.
  - **Vanilla dust has its own private switch**, so plain neighbors would latch each other on. To stop that, Wall Redstone hands vanilla dust 1 less, and strongly powers its wall block at 1 less. Mixed loops then always fade to 0 (covered by a GameTest).

- **Multi-Button Remote:**
  - Stores a `remote_buttons` component: exactly 4 `(frequency, toggle)` buttons plus a selected index. The record constructor normalizes size, selection and frequencies, so bad packets or commands can't break it.
  - Pressing reuses `RemoteControlItem.sendSignal`.
  - Sneak + scroll is caught client-side by the cancellable `InputEvent.MouseScrollingEvent` (so the hotbar doesn't move) and sent as `SelectRemoteButtonPayload`.
  - The keypad sends `ConfigureMultiRemotePayload` (settings, plus an optional button to press). The server checks the item and has a short cooldown.
- **Pulse length:**
  - Stored in ticks, 2–200 (0.1–10s, default 20).
  - The single remote keeps it in its own `remote_pulse_ticks` component. Each Multi-Button Remote button has a `pulse_ticks` field, optional in saved data, so older remotes load as 1s.
  - The screens step through the presets in `PulseLength`. Sneak-click steps down.
  - `RemoteControlItem.sendSignal` takes the length and clamps it.
- **Signal light:**
  - `SignalNetwork` also tracks loaded receivers by frequency (not saved). A receiver checks in on its first tick and when re-tuned, and checks out in `setRemoved`, which covers both breaking and chunk unload.
  - On a press, `sendSignal` counts receivers within reach and sets a `remote_light` component (heard + show-until time). It's synced but never saved.
  - The client registers an item property `reikos_signal_tower:light` (0 off, 0.5 green, 1 red), and the item models' overrides pick the matching texture.
  - Both remotes override `shouldCauseReequipAnimation`, so the light changing doesn't replay the pull-out animation.
- **Button names:**
  - Each `RemoteButtons.Button` has a `name` (optional in saved data, so older remotes load unnamed). The record constructor cleans it with `StringUtil.filterText`, strips spaces and cuts it to 24 characters, on the server and the client alike.
  - `Button.label(index)` gives the name, or "Button N", and every message and tooltip uses it.
- **Button colors:**
  - Each `RemoteButtons.Button` has a `DyeColor color` (optional in saved data; null only on a button that isn't on a remote yet). The `RemoteButtons` constructor fills in its slot's default: red, lime, blue, yellow.
  - The item model has 5 layers (the vanilla maximum): the body (with the status light) and one white-and-grey button per layer 1-4. `MultiRemoteItem.tintColor` (registered in `RegisterColorHandlersEvent.Item`) multiplies each with its button's dye color, so the shading is baked into the greys. The green/red light models use the same button layers.
  - `Button.label` draws the name in `RemoteButtons.textColor`: the dye's color, lightened just enough for dark dyes to stay readable on tooltips.
  - The keypad has a color column: a button with the colored square drawn over it in `render`, click for the next dye, sneak-click for the previous one, and a tooltip naming the color.
- **Radio Pager:**
  - `PagerItem.inventoryTick` runs every tick on the server for each pager in a player's inventory (including off-hand and armor slots) and calls `checkSignal`: `SignalNetwork.listen` at the player's block position, the same rule as a receiver there. Every tick, so even a 0.1s remote pulse is caught.
  - The last strength is kept in a `pager_signal` component (saved, so reloading with the signal on doesn't re-alert; synced, so the client's `pager_on` item property can light the screen). Only a change from 0 to more than 0 alerts.
  - An alert shows an action-bar message (the anvil name if it has one) and plays `NOTE_BLOCK_BIT` (`pager.beep`, one short beep, since v0.59.0) with `ServerPlayer.playNotifySound`, so only the owner hears it. The other two beeps come from a `pager_beeps` component (synced, never saved), one every 4 ticks. `pager_silent` turns the beeps off.
  - Chat log: on by default (`pager_chat_log` component, only stored as `false`). An alert also goes to chat as `PagerItem.chatLine(dayTime, alert)`: "[Day N, HH:MM] " from `level.getDayTime()`, shifted 6000 ticks so days start at midnight (day time 0 is 06:00), then the alert. The pager's screen has Sound and Chat log buttons and saves with `ConfigurePagerPayload`, which only re-tunes (re-arming the alert) if the frequency really changed.
  - Catch-up: `SignalNetwork` keeps, per frequency, the last 32 `TurnOn`s (game time, day time, coverage), recorded when a transmitter goes from off (or absent, or another frequency) to on, on every remote pulse, and when a toggle switches on; saved as `turn_ons`. Stamps come from `tick(gameTime, dayTime)`. `PlayerLoggedOutEvent` → `PagerItem.markAway` stamps every pager with `pager_away_since` (it fires before the player is saved). `PlayerLoggedInEvent` → `PagerItem.catchUp` asks `turnOnsSince(frequency, since, player position)` for each stamped pager, removes the stamp and posts one chat line per pager that missed something, or one "heard nothing" line (skipped for a singleplayer world's owner, since that world is paused while they're away).
  - Re-tuning (`PagerItem.setFrequency`, used by the screen packet, scrolling and copying) clears the stored signal, so the new frequency alerts if it's already on.
  - `RemoteControlItem.sendSignal` adds `PagerItem.countPagers` (pagers on that frequency carried by players inside the coverage) to "Heard by". The locator doesn't include pagers, so it can't track players.
- **Signal Scanner:**
  - `SignalNetwork.scanAt(level, pos)` goes through every transmitter in the dimension and keeps, per frequency, the strongest one whose reach covers `pos` (the nearest, among equally strong ones), plus a count. - **Locator:**
  - An open remote screen sends `RemoteScanRequestPayload` (up to 4 frequencies) every 20 ticks, or sooner after typing. The server only answers players holding a remote.
  - It uses the receiver tracking (`SignalNetwork.scanReceivers`): count within reach, and nearest within 2× reach, with distance and 8-way compass direction.
  - It replies with `RemoteScanResultPayload`, the mod's only server-to-client packet. That goes to `ClientHooks.onRemoteScan`, and from there to the open screen.
  - Nothing is transmitted, and receivers beyond 2× reach are never revealed.
- **Tower relay:**
  - A remote signal covers a list of `SignalNetwork.Coverage` areas (origin, reach, tower flag). The first is the player's own; `remoteCoverage` adds one for every transmitter within the player's reach (horizontally, any frequency), with that transmitter's stored reach. One hop only: towers don't relay to each other.
  - `RemoteControlItem.coverageFor` reads the `towersRelayRemotes` server config (default on). Presses, the "Heard by" count, the light and the locator all use the same coverage.
  - Pressing again during a pulse merges the new areas into it. A latch keeps the areas it was switched on with. A tower area only counts while its transmitter is still there (if its chunk is loaded), so breaking a tower cuts off a latch it was carrying within a second.
  - Latches save a `coverage` list, plus the old `pos`/`reach` keys (the player's own area) so older versions can still read them. Old saves without `coverage` load as just the player's area.
  - The locator's "nearest" hint covers receivers within 2× the player's own reach or inside any relayed area. `RemoteScanResultPayload` also carries the tower count for the screens' reach line.
  - Two older GameTests that check a far receiver hears nothing press with relays left out, because the GameTest grid puts other tests' transmitters within reach.
- **Input:** a transmitter's input is the strongest of `getBestNeighborSignal` at the transmitter and at every mast in the unbroken column directly below it.

## How it works

- `SignalNetwork` is `SavedData`, one per dimension. It maps transmitter position → (frequency, power, reach), indexed by frequency, with a revision counter per frequency (not saved).
- **Repeaters and converters** are kept the same way: position → `Repeater(frequency, output, reach)` (a repeater has `output == frequency`), indexed both by the frequency they listen on and the one they send on, saved as `repeaters` (`output` only written for converters, so 0.20.0 saves load as repeaters). `RadioRepeaterBlockEntity` (shared by both blocks; a converter keeps its `output_frequency`) checks in on its first tick, when re-tuned and once a second; `onRemove` takes it out. What each sends isn't stored but worked out by `SignalNetwork.resolve(level)`:
  - each starts with what it hears straight from transmitters and remote signals on the frequency it listens on (`listenDirect`);
  - then, strongest first, each one that hears something passes that strength to the repeaters and converters inside its reach that listen on the frequency it sends on (a max-strength spread, O(n²) over the dimension). Because it only spreads out from real sources, a loop of repeaters, or of converters going A → B → A, with no source stays at 0.
  - One answer for the whole dimension, cached by `relayEpoch`, which goes up on any change to a relay and whenever a frequency some relay listens on is bumped; also re-worked after 20 ticks (for changes nothing reports, such as a remote's relay tower being broken). Stale entries (block gone, chunk loaded) are dropped while resolving.
  - `bump(frequency)` also bumps the output frequencies of converters listening on it, and so on down the line (with a visited set for loops), so receivers on a converted frequency re-scan as soon as the source changes.
  - `listen` = `listenDirect` plus every repeater/converter sending on that frequency whose reach covers the position (its resolved strength; counts toward `transmittersInReach`). So receivers, pagers and everything else built on `listen` hear them with no changes of their own.
  - `carried(level, frequency, coverage)` extends a coverage list through repeaters and converters (breadth-first over (frequency, area) pairs, each relay once, not re-adding one already relaying as a tower), giving the areas reached on each frequency plus how many repeaters and converters were added. `RemoteControlItem.sendSignal` uses it for "Heard by" (receivers and pagers on every frequency reached), the light and the "+ N repeaters + N converters" in the message; `recordTurnOn` stores a turn-on on every frequency it reached, so the pager catch-up covers converted frequencies too. `withRepeaters` is its same-frequency part, used by the locator.
  - `remoteCoverage` adds repeaters and converters as relay towers next to transmitters, and `RemoteSignal.reaches` accepts any of them (`SignalNetwork.isTower`).
  - The scanner's `bestTransmitters` also offers each repeater and converter covering the position, under the frequency it sends on (resolved strength, `Source.REPEATER` or `Source.CONVERTER`, added at the end of the enum since it's sent by ordinal). Ties go to the stronger, then nearer, then a transmitter. Tracking accepts any of them (`towerFrequencyAt` gives the frequency it sends on).
  - Converter screen: `RadioConverterBlock.useWithoutItem` sends `OpenConverterScreenPayload` (position, both frequencies, current strength, reach; block entities aren't synced) to the player; `ConverterScreen` sends `ConfigureConverterPayload` back, which only applies if `player.canInteractWithBlock(pos, 1.0)` and the block is a converter, then sets both with `setFrequencies`.
- **Transmitters** update their entry when:
  - a neighbor changes,
  - a mast in their column reports a change (masts walk up their column on neighbor change, placement and removal),
  - their frequency changes,
  - and once a second in their block entity tick, which also catches config changes and world edits.
- **Receivers** re-scan only when their frequency's revision changes or their own frequency changes, plus a once-a-second fallback. Changes arrive within one tick.
- **Toggle receiver (v0.23.0):** `RadioToggleReceiverBlock extends RadioReceiverBlock` and shares `RadioReceiverBlockEntity` (one block entity type for all three receivers). Each re-scan goes through `outputFor(heard)`: a plain receiver outputs what it heard; a toggle receiver remembers whether it heard anything last time (`lastHeard`, not saved) and flips `toggledOn` (saved as `toggled_on`, only when true) on silent → heard, outputting 15 or 0 through the same `POWER` state. `primed` (not saved) starts false on placement, load and re-tune (`onFrequencyChanged`), so the first check only records what it hears. Pulses bump the revision when they start and end, so even a 0.1s pulse is seen. Turn-ons while unloaded are missed. Jade and the readout use `isToggledOn()`.
- **Cleanup:** entries whose transmitter (or repeater/converter) block is gone are removed the next time something in range scans.
- **Dropped items:** the frequency rides on the item as the `reikos_signal_tower:frequency` data component (a converter also carries `output_frequency`). The block entity's `collectImplicitComponents` adds it, and the loot table's `copy_components` copies it onto the drop. `applyImplicitComponents` reads it back when the block is placed.
- **Tuner:** the screen sends `ConfigureRadioItemPayload` (hand, value, and the remote's mode and pulse length). The server checks the player is holding the right item and clamps the value.
